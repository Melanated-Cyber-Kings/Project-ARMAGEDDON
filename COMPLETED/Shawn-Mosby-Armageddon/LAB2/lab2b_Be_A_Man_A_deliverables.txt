3) One paragraph answering:
    Why origin-driven caching is safer for APIs
    When you would still disable caching entirely

Origin-driven caching is safer because the application developers (who best understand the data's sensitivity) maintain control over how long data lives in the "wild." 
By using headers like s-maxage, the API can dynamically tell CloudFront to cache public data while simultaneously using private, no-store to prevent sensitive or user-specific data (like the /api/list results) from ever being stored on an edge server.

When you would still disable caching entirely: 
You would disable caching entirely for "Real-Time" or "Transaction-Critical" endpoints where a response must be 100% accurate at the millisecond it is requested. 
Examples include stock trading platforms, inventory counts for flash sales, or multi-factor authentication (MFA) prompts. 
In these cases, serving data even 1 second old could result in a failed transaction or a security risk.
